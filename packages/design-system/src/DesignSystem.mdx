# Crux design system

The shared visual language and reusable UI pieces for Crux Club. This guide is part of the design-system package, and the examples below render the same stories used to review the components and tokens.

Use the **Palette** control in the Storybook toolbar to switch between the Crux and Summit semantic palettes. The component names and semantic roles stay the same when the palette changes.

## Design principles

- **Community first:** friendly, clear interfaces for a shared climbing log.
- **Playful but readable:** expressive illustrations and warm colors sit beside simple layouts and clear type.
- **Consistent by tokens:** components consume semantic and component tokens instead of embedding palette values.
- **Easy to reskin:** change the primitive palette or select another semantic palette without rewriting components.

## Token layers

The tokens are defined in `src/tokens/`. Each layer answers a different question:

| Layer | Purpose | Examples |
| --- | --- | --- |
| Primitives | Which raw values are available? | `--primitive-color-plum-800`, `--primitive-space-4`, `--primitive-font-size-md` |
| Semantic | What role does a value play in the interface? | `--color-surface`, `--color-text-primary`, `--space-card-inset` |
| Component | How does a reusable component apply those roles? | `--component-button-primary-background`, `--component-card-radius` |

Viewport breakpoints are exported from `@crux/design-system/breakpoints` as an ascending, mobile-first scale (`xs` through `xl`) and matching `min-width` media queries. They are JavaScript tokens because CSS custom properties cannot be used in `@media` rules.

Prefer a semantic token in app and component styles. Change a palette by remapping semantic roles in `semantic.css`; reserve primitive values for palette definitions and token previews. Add component tokens when a shared component needs a stable, independently tunable value.

Primitive spacing uses a four-pixel base step. Semantic spacing names express intent, such as a card inset or section gap; component tokens can tune a reusable component without changing the scale.

### Responsive breakpoints

Use the shared viewport widths to keep responsive transitions consistent across the app. Start with styles for the smallest screens, then layer in wider layouts with `mediaQueries` from `@crux/design-system/breakpoints`. This follows the screen-width and minimum-width query pattern used by [Mozilla Protocol](https://protocol.mozilla.org/docs/fundamentals/design-tokens).

## Use the package in the app

```jsx
import { Button, Surface } from '@crux/design-system';
import '@crux/design-system/tokens.css';

<Surface>
  <h2>Today’s sends</h2>
  <Button variant="primary">Log a send</Button>
</Surface>
```

The app sets `data-palette="crux"` on its root element. Change it to `summit` to preview the alternate palette. Keep page-specific layout and behavior in the app; put reusable visual patterns, tokens, and illustrations in this package.

## Extend the system

1. Add raw values only to the primitive layer.
2. Map each palette to the same semantic roles.
3. Add a component token when a reusable control needs a named override.
4. Add or update a Storybook story beside the component or token it documents.
5. Check the component in both palette modes and at narrow and wide sizes before using it across app pages.
